Where the data comes from

Everything here is built from Macondo's public API — the same endpoints any visitor's browser uses on project pages. No login, no API key, nothing private.

  • /api/projects/{id} — project record, including live ship status
  • /api/projects/{id}/ships — every ship with submission date, decision date, outcome, hours, reviewer message
  • /api/users/{username} — a user's public project list
  • /api/explore/* — public project gallery and people directory (used for enumeration)

A nightly job enumerates users → projects → ships at a polite rate (~1 request/second, honoring rate limits) and commits a snapshot. Your own project lookup happens live in your browser, so the moment your status changes, you see it — everything else is at most ~24h old, and labeled with its timestamp.

Which projects are counted (the submission cutoff)

The dashboard measures a fixed population: projects whose original submission landed on or before 31 August 2026, 23:59:59 UTC+0. Freezing the set this way is what makes "when will the backlog clear?" a question with an answer — a queue that keeps growing never drains, so the estimate would be meaningless.

The cutoff is decided per project, not per ship, and that distinction matters:

  • Counted: every ship of a counted project — including resubmissions after a change request and second-pass reviews submitted after the cutoff. These are the same project still moving through the pipeline, so dropping them would understate the work.
  • Left out: projects whose first ever submission came after the cutoff. They are visible in Macondo and their own lookup page here still works, they just aren't part of the backlog measured.

Every date and time on this site is UTC+0 — the cutoff date, the snapshot timestamp, and all submission and decision dates. Your browser's local timezone is never applied.

The review pipeline, from public data

A "ship" (project submission) moves through stages:

  1. In review — sits in the reviewer queue. Reviewers claim ships individually (like a shared inbox, not a conveyor belt). Whether yours is currently claimed is not public.
  2. Fraud check (sometimes) — a ship may be escalated to the fraud squad, which checks an external fraud API and returns a verdict asynchronously. Shown publicly only as a distinct status while it's pending.
  3. Second pass — once a reviewer approves, the ship waits on a final double-check by an admin ("ARI") before the reward is released. Your project shows "accepted — waiting on a final second-pass check" here.
  4. Shipped — reward released, project public on the gallery.

Other outcomes: needs changes (revise and resubmit — a new ship) and rejected (sometimes fraud-related, which the public ship record marks).

How the estimate is computed

Three signals, blended:

  • Queue position — your ship's age rank among all waiting ships, from the snapshot. (Guidance, not a line number — claims jump around.)
  • Front velocity — recent decisions were on ships submitted around date X; the front advances at some submissions-per-day; the distance from X to your submission date ÷ that rate ≈ your wait.
  • Cohort survival — of ships submitted in your week, what fraction were decided within 7/14/30 days.

That's why we show a range with a median, never a single date.

What this can never know — accuracy, honestly

  • Whether a reviewer has already claimed your ship. Claim/assignment state exists only in the reviewer-only interface. Two identical "in review" ships can be in completely different situations.
  • Reviewer availability. Throughput varies ~4× between active weeks and quiet weeks; we use the trailing 14 days.
  • Fraud-review detours. Escalation and verdict timing are external.

Estimates are distributions, not promises. The fast-lane stat (~16% of ships decided within 24h) is real and worth remembering: any ship can be claimed any day, regardless of the queue math.

If Macondo ever exposed a claimed/unclaimed flag publicly, the error bars on these estimates would shrink dramatically. This site is, in part, a demonstration that the public data is rich enough to want it.

Etiquette

The nightly snapshot costs Macondo's API ~1,500 polite requests total (cached output served to every visitor after that). Each project lookup is 2 requests, live. If you use this code, keep the rate limits and the User-Agent contact string — don't be the reason an endpoint closes.
